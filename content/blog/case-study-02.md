<h2>들어가며</h2><p>축제 맵에 주점 마커를 띄우려면 결국 누군가는 주점마다 좌표를 하나하나 입력해야 합니다. 사용자 화면만 신경 쓰다 보면 이 "누군가"의 수고는 잘 안 보입니다. 이번 글은 그 작업을 줄이려고 만든 내부 관리 페이지 이야기입니다.</p><h2>주소가 없는 주점</h2><p>축제 주점에는 주소가 없습니다. "공대 앞 잔디밭 세 번째 부스" 같은 위치를 지도 좌표로 바꾸려면, 운영자가 지도를 켜 놓고 해당 위치를 찾아서 좌표를 복사하고 붙여 넣어야 했습니다.</p><p>주점 하나면 괜찮은데 수십 개를 이렇게 하다 보면 금방 지치고, 지치면 실수가 나옵니다. 좌표를 한 자리만 잘못 붙여 넣어도 주점이 전혀 다른 곳에 찍힙니다.</p><h2>처음엔 매뉴얼을 만들었다</h2><p>처음 떠올린 해결책은 좌표 입력 매뉴얼이었습니다. 순서대로 따라 하면 누구나 정확하게 입력할 수 있게 만들면 되겠다고 생각했습니다.</p><p>실제로 해 보니 생각과 달랐습니다. 지도를 다루는 게 익숙한 사람과 아닌 사람의 차이가 커서 입력 정확도가 들쭉날쭉했고, 위치가 틀리면 수정 요청이 몇 번씩 오갔습니다. 축제 준비로 가장 바쁜 주점 관리자들에게 일을 하나 더 얹는 셈이기도 했습니다.</p><p>그때 문제는 사람이 아니라 방식이라는 생각이 들었습니다. 좌표를 "찾아서 옮겨 적는" 단계 자체를 없애야 했습니다.</p><h2>지도를 누르면 좌표가 생기게</h2><p>그래서 지도를 보면서 원하는 위치를 클릭하기만 하면 좌표가 저장되는 관리 페이지를 만들었습니다. 쓰는 흐름은 이렇습니다.</p><ol><li><p><code>시작</code> 버튼을 누르면 좌표 생성 모드가 켜집니다.</p></li><li><p>지도를 클릭하면 마커가 생기고, 스토어 ID를 입력하는 팝업이 뜹니다.</p></li><li><p>입력한 스토어 ID와 클릭한 위치의 좌표(lat, lng)가 묶여서 저장됩니다.</p></li><li><p>다 찍었으면 <code>중지</code> 버튼으로 모드를 끕니다.</p></li><li><p><code>복사</code> 버튼을 누르면 저장된 좌표 전체가 문자열로 복사됩니다.</p></li></ol><pre><code class="language-typescript">// 예시 코드: 지도 클릭 시 스토어 ID와 좌표를 매핑해 저장
naver.maps.Event.addListener(map, "click", (e) =&gt; {
  if (!isCreating) return;

  const storeId = window.prompt("스토어 ID를 입력하세요");
  if (!storeId) return;

  const marker = new naver.maps.Marker({ position: e.coord, map });
  markers.push({ storeId, lat: e.coord.lat(), lng: e.coord.lng(), marker });
});</code></pre><p>만들면서 제일 신경 쓴 건 실수했을 때 되돌리는 방법이었습니다. 마커를 수십 개 찍다가 하나 잘못 찍었는데 처음부터 다시 해야 한다면 저라도 짜증이 날 것 같았습니다. 그래서 마지막 마커 하나만 지우는 <code>뒤로가기</code>와 전부 지우는 <code>초기화</code>를 따로 뒀습니다.</p><p>실제로 쓰는 모습은 영상으로 남겨 두었습니다: <a href="https://www.youtube.com/watch?v=qFZTqwZ5DaQ" target="_blank" rel="noopener noreferrer">시연 영상 보기</a></p><h2>결과</h2><ul><li><p>주점 위치 등록 시간이 <strong>15분에서 5분 이내</strong>로 줄었습니다. (약 65% 개선)</p></li><li><p>좌표를 손으로 옮겨 적는 과정이 사라져서 입력 실수도 거의 없어졌습니다.</p></li></ul><h2>돌아보며</h2><p>사용자가 보는 화면만큼, 그 화면을 준비하는 사람의 작업도 서비스 품질에 그대로 영향을 준다는 걸 느꼈습니다. 매뉴얼로 사람을 맞추려고 했던 건 돌이켜 보면 쉬운 길이었고, 도구를 바꾸는 쪽이 훨씬 확실했습니다.</p>
