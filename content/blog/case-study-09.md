problem: |-
  사용자 정보와 리뷰 데이터를 하나의 API로 함께 조회해, 초기 진입 시 **당장 필요 없는 리뷰 데이터까지 한 번에 요청**하는 문제 발생
  페이지네이션 이후에도 스크롤할수록 리뷰 컴포넌트가 **DOM에 계속 누적**되어 렌더링 및 스크롤 성능 저하

  **useInfiniteQuery**를 활용한 리뷰 데이터 페이지 단위 조회
  **react-virtual Windowing**으로 화면에 보이는 리뷰만 DOM에 렌더링
result: |-
  초기 진입 시 불필요한 리뷰 데이터 요청을 제거해 초기 데이터 요청 시간 **약 0.6초 → 0.1초 단축**
  테스트 환경(이미지 포함 데이터 500개) 기준 초기 로딩 시간 **약 7초 → 1.2초 단축**
  리뷰와 이미지가 늘어나도 DOM 요소 수를 일정하게 유지해 **안정적인 스크롤 성능** 확보

<h2>개요</h2><p></p><img src="/assets/blog/best-review-1.png" width="1956" height="1405"><p></p><p>&nbsp;</p><p>마이셀렉트샵의 UI는 사이드 패널을 기반으로 구성되어 있어 여러 페이지가 하나의 화면에서 토글되는 구조입니다.</p><p>지역 베스트 리뷰 페이지에서는 먼저 베스트 리뷰어의 사용자 정보를 보여주고, 사용자를 선택하면 해당 사용자의 리뷰 목록을 확인할 수 있습니다.</p><p>기존에는 사용자 정보와 리뷰 데이터를 하나의 API에서 함께 조회하고 모든 리뷰를 한 번에 렌더링하고 있어, <strong>리뷰 데이터가 많아질수록 초기 로딩과 스크롤 성능이 저하되는 문제</strong>가 발생했습니다.</p><p>이를 해결하기 위해 <strong>데이터 요청과 렌더링을 분리하고, 필요한 데이터를 필요한 시점에 가져오는 구조로 개선</strong>했습니다.</p><ul><li><p>사용자 정보와 리뷰 데이터 API 분리</p></li><li><p>useInfiniteQuery를 활용한 리뷰 데이터 페이지네이션</p></li><li><p>react-virtual을 활용한 Windowing 적용</p></li></ul><p>아래에서 조금 더 자세하게 다뤄보도록 하겠습니다.</p><h2>&nbsp;</h2><h2>문제 1. 초기 진입 시 불필요한 리뷰 데이터 요청</h2><p>기존에는 사용자 정보와 리뷰 데이터를 하나의 API 응답으로 함께 반환하고 있었습니다.</p><p>사용자 정보는 페이지 진입 시 바로 필요했지만, 리뷰 데이터는 실제 리뷰 목록을 렌더링할 때 필요했습니다. 그럼에도 사용자 정보를 조회하는 과정에서 리뷰 데이터까지 함께 받아오면서 <strong>초기 요청에 불필요한 데이터가 포함되는 문제</strong>가 있었습니다.</p><p>특히 리뷰에는 이미지와 같은 비교적 큰 데이터도 포함되어 있어 리뷰가 많아질수록 초기 네트워크 요청량과 렌더링 비용이 증가했습니다.</p><h3>&nbsp;</h3><h2>해결 과정</h2><h4>1. 사용자 정보와 리뷰 데이터 API 분리</h4><p>사용자 정보 조회 API와 리뷰 조회 API를 분리했습니다.</p><p>기존에는 사용자 정보와 전체 리뷰 데이터를 한 번에 요청했지만, 개선 후에는 <strong>사용자 정보만 먼저 조회하고 리뷰 데이터는 별도로 요청</strong>하도록 변경했습니다.</p><p>&nbsp;</p><p>&nbsp;</p><p><strong>유저 데이터에 리뷰 리스트가 포함되어 있는 구조</strong></p><p></p><img src="/assets/blog/best-review-2.png" width="229" height="277"><p></p><p>&nbsp;</p><p>&nbsp;</p><p><strong>사용자 정보와 리뷰 데이터를 별도로 조회하는 구조</strong></p><p></p><img src="/assets/blog/best-review-3.png" width="771" height="232"><p></p><h2>&nbsp;</h2><p>이를 통해 초기 화면 구성에 필요하지 않은 리뷰 데이터를 초기 요청에서 제거했습니다.</p><h4>&nbsp;</h4><h4>2. useInfiniteQuery를 활용한 페이지네이션</h4><h4>&nbsp;</h4><p>리뷰 데이터를 한 번에 전체 조회하지 않고, useInfiniteQuery를 활용해 <strong>페이지 단위로 조회하도록 변경</strong>했습니다.</p><p>초기에는 일정 개수의 리뷰만 요청하고, 사용자가 스크롤하여 추가 데이터가 필요해지는 시점에 다음 페이지를 요청하도록 구성했습니다.</p><p>&nbsp;</p><p>하지만 실제 서비스에서는 리뷰 데이터의 양이나 사용자 트래픽에 따라 성능 차이를 일정하게 비교하기 어려웠습니다. 또한 테스트 환경에서는 실제 사용자가 충분하지 않아 개선 효과를 객관적으로 확인하기 어려웠습니다.</p><p>따라서 <strong>동일한 조건에서 페이지네이션 적용 전후의 차이를 확인할 수 있도록 별도의 테스트 레포지토리를 구성</strong>했습니다.</p><p>먼저 리뷰 데이터 <strong>500개를 한 번에 조회하는 경우와 페이지 단위로 조회하는 경우를 비교하여 초기 로딩 시간의 차이</strong>를 확인해보겠습니다.</p><p>&nbsp;</p><p>&nbsp;</p><p><strong>이미지를 포함한 데이터 500개를 한 번에 조회</strong></p><p></p><img src="/assets/blog/best-review-4.png" width="829" height="80"><p></p><p>&nbsp;</p><p>&nbsp;</p><p><strong>이미지를 포함한 데이터 500개를 페이지 단위로 조회</strong></p><p></p><img src="/assets/blog/best-review-5.png" width="848" height="76"><p></p><p>&nbsp;</p><p>데이터 500개를 한 번에 조회했을 때 초기 로딩 시간은 <strong>약 7초</strong>가 소요되었습니다. 반면, 동일한 500개의 데이터를 페이지당 10개씩 나누어 조회했을 때는 <strong>약 1.2초</strong>로 초기 로딩 시간이 크게 감소했습니다.</p><p>이를 통해 초기 진입 시 한 번에 요청하는 데이터의 양을 줄이는 것만으로도 <strong>초기 로딩 시간을 약 5.8초 단축</strong>할 수 있음을 확인했습니다.</p><p>&nbsp;</p><p>처음에는 10,000개의 데이터를 기준으로 테스트하려고 했습니다. 하지만 테스트 환경의 컴퓨터 성능상 10,000개의 데이터를 한 번에 처리하기에는 무리가 있었고, 현실적으로 테스트할 수 있는 범위인 500개의 데이터를 기준으로 실험을 진행했습니다.</p><p>&nbsp;</p><p>물론 500개의 데이터가 실제 서비스의 데이터 규모를 그대로 대변한다고 보기는 어렵습니다. 하지만 같은 환경에서 페이지네이션 적용 전후를 비교함으로써, 데이터 조회 방식에 따라 초기 로딩 시간이 얼마나 달라지는지는 확인할 수 있다고 판단했습니다. 따라서 이번 테스트에서는 절대적인 수치보다는 페이지네이션 적용에 따른 성능 차이를 확인하는 데 의미를 두었습니다.</p><h3>&nbsp;</h3><h2>결과</h2><p>사용자 정보와 리뷰 데이터를 분리하고 리뷰 데이터를 페이지 단위로 조회하면서</p><p><strong>초기 진입 시 불필요한 데이터 요청을 제거하여 초기 데이터 요청 시간은약 0.6초 → 0.1초로 단축</strong>하였습니다.</p><h2>&nbsp;</h2><h2>문제 2. 리뷰 증가에 따른 렌더링 및 스크롤 성능 저하</h2><p>&nbsp;</p><p>페이지네이션을 적용하더라도 사용자가 계속 스크롤하면 가져온 리뷰 데이터가 계속 누적되었습니다.</p><p>예를 들어 100개의 리뷰를 가져온 경우 실제 화면에 보이는 리뷰가 10개 정도뿐이어도 <strong>100개의 리뷰 컴포넌트가 모두 DOM에 존재</strong>하게 됩니다.</p><p>리뷰와 이미지가 많아질수록 DOM 요소가 증가하고, 스크롤 과정에서 렌더링 및 레이아웃 처리 비용이 커지는 문제가 있었습니다.</p><h3>&nbsp;</h3><h2>해결 과정</h2><h4>react-virtual을 활용한 Windowing 적용</h4><p>react-virtual의 Windowing을 적용해 <strong>전체 데이터를 가지고 있더라도 실제 화면에 보이는 영역과 주변의 일부 데이터만 DOM에 렌더링</strong>하도록 변경했습니다.</p><p>사용자가 스크롤하면 화면에 들어오는 리뷰만 렌더링하도록 하여, 리뷰 데이터가 증가하더라도 <strong>실제 DOM에 존재하는 요소의 수를 일정 수준으로 유지</strong>할 수 있도록 했습니다.</p><p>&nbsp;</p><p></p><img src="/assets/blog/best-review-6.png" width="938" height="492"><p></p><h3>&nbsp;</h3><h2>결과</h2><p>useInfiniteQuery로 필요한 만큼의 데이터만 가져오고, react-virtual의 Windowing으로 그중 <strong>실제 화면에 필요한 요소만 DOM에 렌더링</strong>하도록 개선했습니다.</p><p>이를 통해 리뷰와 이미지가 많아지는 상황에서도 DOM이 증가하지 않도록 방어하고, <strong>대량의 리뷰 데이터에서도 안정적인 스크롤 성능을 유지</strong>할 수 있었습니다.</p><p></p><p></p><h2>&nbsp;마무리</h2><p>이번 개선에서는 단순히 API 호출 시간을 줄이는 것보다 <strong>데이터를 언제 가져오고, 언제 렌더링할 것인지​</strong>를 분리해서 접근했습니다.</p><p>먼저 사용자 정보와 리뷰 데이터를 분리해 초기 진입에 필요하지 않은 데이터를 제거하고, useInfiniteQuery를 통해 리뷰 데이터를 점진적으로 가져왔습니다. 이후 react-virtual을 적용해 가져온 데이터 중에서도 실제 화면에 필요한 요소만 렌더링하도록 개선했습니다.</p><p>결과적으로 <strong>데이터 요청 → 데이터 로딩 → DOM 렌더링</strong>의 각 단계에서 불필요한 작업을 줄여 초기 진입 성능과 대량 데이터 환경에서의 스크롤 성능을 함께 개선할 수 있었습니다.</p>
