<h2>들어가며</h2><p>서비스에 조금 생기를 주고 싶어서 애니메이션 이미지를 넣었습니다. 그런데 오히려 첫인상을 망치고 있었습니다. 페이지에 들어가자마자 애니메이션이 뚝뚝 끊기면서 시작되는 겁니다. 의도한 것과 정반대의 효과였습니다.</p><h2>왜 끊겼을까</h2><p>애니메이션 이미지는 일반 이미지보다 용량이 훨씬 큽니다. 페이지가 뜨는 시점에 이미지가 아직 다 받아지지 않은 상태에서 재생이 시작되니, 프레임이 중간중간 비면서 끊겨 보였던 겁니다.</p><p>그렇다고 애니메이션을 빼기는 아까웠습니다. 문제는 애니메이션 자체가 아니라 준비가 덜 된 상태에서 보여 준다는 점이었으니까요.</p><h2>가벼운 걸 먼저 보여 주고, 무거운 건 뒤에서 준비하기</h2><p>그래서 순서를 바꿨습니다. 처음에는 가벼운 정적 이미지를 보여 주고, 그동안 애니메이션 이미지를 화면 뒤에서 미리 받아 둔 다음, 준비가 끝나면 바꿔 끼우는 방식입니다.</p><p>미리 받아 두는 데는 브라우저의 <code>Image</code> 객체를 썼습니다. <code>new Image()</code>로 만든 이미지는 화면에 붙이지 않아도 브라우저가 알아서 다운로드하고 캐시에 남겨 둡니다. 그래서 나중에 진짜 이미지로 바꿀 때는 이미 준비된 걸 꺼내 쓰기만 하면 됩니다.</p><pre><code class="language-tsx">// 예시 코드
const [src, setSrc] = useState(FALLBACK_SRC);

useEffect(() =&gt; {
  const image = new Image();
  image.src = ANIMATED_SRC;
  image.onload = () =&gt; setSrc(ANIMATED_SRC);

  return () =&gt; {
    image.onload = null;
  };
}, []);

return &lt;img src={src} alt="" /&gt;;</code></pre><img src="/assets/fallback.png" alt="정적 fallback 이미지 적용 후 초기 렌더링 비교"><h2>결과</h2><ul><li><p>애니메이션이 시작될 때 끊기던 현상이 사라졌습니다.</p></li><li><p>페이지에 처음 들어왔을 때 화면이 훨씬 안정적으로 보이게 되었습니다.</p></li></ul><h2>돌아보며</h2><p>작업 자체는 크지 않았는데 체감은 꽤 컸습니다. 무거운 걸 빼는 것만이 방법은 아니고, 언제 보여 줄지만 바꿔도 결과가 달라질 수 있다는 걸 알게 됐습니다.</p>
