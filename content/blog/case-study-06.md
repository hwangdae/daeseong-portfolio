description: "폰트 최적화"
date: '2026-09-12'
problem: |-
  여러 굵기와 스타일의 로컬 폰트를 각각 개별 파일로 로드하는 구조 사용으로 **네트워크 요청 수와 총 다운로드 용량이 함께 증가** 및 초기 페이지 진입 시 렌더링이 지연되는 현상이 발생
solution: |-
  **Woff2** 파일 포맷으로 통합 변환
  **가변 폰트(Variable Font)** 도입
  **서브셋 웹 폰트** 변환
result: |-
  폰트 파일 용량 **6MB -> 476KB**로 축소 (**약 90% 용량 절감**)
  TBT(Total Blocking Time) 개선을 통한 LightHouse Performance 점수 **54점 → 84점**으로 향상

<h2>들어가며</h2><p>마이셀렉트샵은 처음 세팅부터 배포까지 혼자 만든 개인 프로젝트입니다. 어느 정도 기능이 갖춰졌을 때 Lighthouse를 돌려 봤는데, Performance 점수가 54점이었습니다. 이미지도 많지 않은데 왜 이렇게 낮은지 의아했습니다.</p><h2>범인은 폰트였다</h2><p>하나씩 따라가 보니 폰트가 문제였습니다. 굵기와 스타일마다 폰트 파일을 따로 불러오고 있었고, 다 합치면 약 6MB였습니다. 텍스트 몇 줄 보여 주려고 6MB를 받고 있었던 겁니다.</p><p>파일이 여러 개이니 요청도 많았고, 그 폰트들이 다 받아질 때까지 텍스트와 레이아웃이 자리를 잡지 못했습니다. 게다가 서비스에서 쓰지도 않는 글자까지 전부 파일에 들어 있었습니다.</p><h2>세 단계로 줄였다</h2><h3>Woff2로 변환</h3><p>먼저 웹 전송에 맞게 압축된 Woff2 포맷으로 바꿨습니다. 폰트 자체는 그대로인데 파일 크기만 줄어드는, 가장 부담 없는 첫 단계였습니다.</p><h3>가변 폰트로 합치기</h3><p>다음은 굵기마다 따로 있던 파일을 가변 폰트 하나로 합치는 것이었습니다. 가변 폰트는 파일 하나 안에서 굵기를 자유롭게 조절할 수 있어서, 요청 수도 줄고 관리할 파일도 하나로 줄었습니다.</p><pre><code class="language-css">/* 예시 코드: 굵기별 여러 파일 대신 가변 폰트 하나로 선언 */
@font-face {
  font-family: "MyFont";
  src: url("/fonts/MyFontVariable.subset.woff2") format("woff2-variations");
  font-weight: 100 900;
  font-display: swap;
}</code></pre><h3>쓰는 글자만 남기기</h3><p>한글 폰트가 무거운 가장 큰 이유는 글자 수입니다. 그래서 서비스에서 실제로 쓰는 글자 영역만 남기는 서브셋 폰트로 바꿔서 한 번 더 줄였습니다.</p><h2>결과</h2><ul><li><p>폰트 용량이 <strong>6MB에서 476KB</strong>로 줄었습니다. (약 90% 절감)</p></li><li><p>TBT(Total Blocking Time)가 줄면서 Lighthouse Performance 점수가 <strong>54점에서 84점</strong>으로 올랐습니다.</p></li></ul><h2>돌아보며</h2><p>성능 개선이라고 하면 코드부터 뜯어볼 생각을 했는데, 이번엔 폰트 파일 하나가 점수를 좌우하고 있었습니다. 감으로 찾았으면 아마 한참 엉뚱한 곳을 봤을 것 같고, 측정부터 해 본 게 결정적이었습니다. 그 뒤로는 새 리소스를 추가할 때마다 용량을 먼저 확인하게 됐습니다.</p>
